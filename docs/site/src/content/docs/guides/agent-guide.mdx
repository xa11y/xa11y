xa11y reads and drives desktop application UIs through each platform's
accessibility API (AX on macOS, UI Automation on Windows, AT-SPI2 on Linux).
This guide describes the tools `xa11y mcp` serves, for an agent driving them.
The binary embeds it, so it matches the version you are talking to. `xa11y mcp`
serves it as the `xa11y://guide` resource and the `guide` prompt, and
`xa11y guide` prints it.

The command line runs the same operations with two differences. `xa11y action`
acts on the first match instead of refusing a selector that matches several.
A failure is an exit code (1 for a failed operation, 2 for a usage error) and a
message on standard error, without the `kind` and `diagnosis` fields described under
Failures.

## Workflow

1. List running applications with `apps`.
2. Read one application's structure with `tree`, giving `app` or `pid`. Start
   with a small `max_depth` such as 2 or 3, then read deeper where you need to.
3. Locate elements with `find` and a selector.
4. Act on one element with `action`.
5. Read the tree again, or call `find`, to confirm what the action changed.

`action` calls the application's own accessibility action, so it works without
window focus and without the element being on screen. The coordinate tools
(`click`, `move`, `drag`, `scroll`, `key`, `type`) post synthetic input
instead. Use them for what has no accessibility action, such as a drag. They
take screen coordinates, which `find` reports as each match's `bounds` and
`center`. If the target may still be moving, call `find` with `stable: true`
first. It waits for the one match to hold still, so the coordinates are where
it comes to rest.

OS shell UI is reached the same way. `shell` lists the surfaces on screen,
such as the taskbar, the dock, panels, the menu bar, status items and open
flyouts. `tree`, `find` and `action` then take a `shell` argument in place of
`app`.

## Selectors

Selectors are CSS-like, as in `button[name="OK"]` or `window > group button`.
The full grammar is in the [selector reference](/reference/selectors/).
These are the rules agents get wrong most often:

- Roles are written in `snake_case`: `check_box`, `radio_button`, `text_field`.
- `=` is case-sensitive. `*=`, `^=` and `$=` ignore case.
- Every attribute filter needs an operator and a value. `[checked]` is a syntax
  error; write `[checked="on"]`.
- `:nth(n)` is the only pseudo-class, and it counts from 1. `:first-child`,
  `:checked` and similar forms fail to parse.
- Table and list positions are numeric attributes that take a quoted integer
  and only `=`: `table_cell[row="2"][column="0"]`, `list_item[index="0"]`.
  They count from 0, like every index except `:nth`.

## Actions

`action` takes a verb, a selector, and a target. The verbs are `press`,
`focus`, `blur`, `toggle`, `expand`, `collapse`, `select`, `show-menu`,
`scroll-into-view`, `increment`, `decrement`, `set-value`,
`set-numeric-value`, `type-text`, `select-text`, and the window verbs
`activate`, `minimize`, `maximize`, `enter-fullscreen`, `restore`, `close`,
`move-to` and `resize-to`.

The selector must match exactly one element. A selector matching several is
refused with an `ambiguous_selector` failure that lists the candidates, and no
element is touched. Narrow it with an attribute filter or pick one with
`:nth(n)`.

`action` auto-waits. It polls until the selector matches one element that is
visible and enabled, then acts on that element. The window verbs and
`scroll-into-view` wait only for enabled, because a minimized window or a
scrolled-away element is invisible by design. When the element is enabled and
the platform reports it as scrolled out, the wait asks the application to
scroll it into view and checks again. A disabled element is never scrolled,
and macOS never reports scrolled out. If the wait tried to scroll, the
`timeout` failure's `auto_scroll` field says how that ended: `refused`,
`no_effect` or `revealed`. The wait lasts up to the default
timeout: 5 seconds unless `XA11Y_DEFAULT_TIMEOUT` sets another number of
seconds in the server's environment. A call that fails takes that
long, and its `timeout` failure names what it waited for and what it last saw.
The wait is already a retry loop, so wrapping `action` in another one only
multiplies the delay.

`ok: true` reports that the platform accepted the call. A control may accept an
action and ignore it, so confirm the effect by reading the tree again.

An element's `actions` field lists what the application advertises through the
platform's action interface. That list is neither the set of verbs `action`
accepts nor a capability list. Pick the verb from the element's other
properties. `increment`, `decrement` and `set-numeric-value` apply to anything
reporting `numeric_value`. `set-value`, `type-text` and `select-text` apply to
anything whose `states` include `editable`. `toggle` applies to anything with a
`checked` state, `expand` and `collapse` to anything with `expanded`, and
`press` to any control.

## Text and tables

`text` reads an element's text by range. Its `op` is `info` (length, caret,
selections), `read`, `find`, `range-at`, `lines`, `bounds` or `runs`. Offsets
are UTF-16 code units, so an emoji outside the Basic Multilingual Plane counts
as two. Every range in a result carries its `start`, `end` and `text`. Copy
those numbers into `select-text` or the next `text` call instead of counting
characters yourself. A range can also be named by its text: `find` with an
optional 0-based `occurrence` selects the match, so `bounds` of
`find: "Total"` returns that word's rectangle.

`table` answers structure questions a selector cannot: `cell-at` returns the
merged cell covering a slot, and the header operations return the headers of a
table or of one cell. Elements from `tree`, `find` and `table` carry `cell`,
`table_row`, `table` and `collection` objects when the platform reports
positions.

## Results

Every result is bounded and reports what it dropped.

- `tree` stops at `max_depth` (default 12) and at a fixed node cap. Its
  `truncated` field says which limit cut the result.
- `find` returns at most `limit` matches (default 50). `match_count` gives the
  real total and `truncated` says whether any were dropped.
- `text` pages its reads. `read` returns at most `limit` code units, and
  `lines` and `runs` at most `limit` entries, each with `truncated` and
  `next_start` for the next page.
- `windows`, `table`, `events_poll` and the `annotate` legend of `screenshot`
  carry their own `truncated` fields.

`tree` also marks each place it cut. A node whose children were dropped by
`max_depth` or the node cap carries `subtree_truncated: true` and
`children_count`, its real number of children. Its `children`, if present, are
only the first ones. A node without `subtree_truncated` is complete, so a node
with no `children` is a leaf. To see a cut subtree, call `tree` or `find` on it.

A single element is bounded too. `name`, `value` and `description` are each cut
to 1024 bytes. A cut field is followed by `<field>_truncated: true` and
`<field>_bytes`, the full length in bytes. Selectors still match the full text,
so `[name^="..."]` finds an element by a prefix of a long name.

An element's `states` object follows three rules:

- `enabled` and `visible` are always present, as `true` or `false`.
- `focused`, `focusable`, `active`, `editable`, `selected`, `modal`,
  `required`, `busy` and `password` appear only when true, so an absent one is
  false. `password` marks a password field, whose role stays `text_field`.
- `checked`, `expanded`, `minimized`, `maximized` and `fullscreen` appear only
  when the platform reports them, so an absent one is unknown.

## Failures

A failed tool call returns `isError: true` with a structured payload. Its
`kind` field is one of the tags below, and its `diagnosis` carries what the
call looked for, what it last observed, and near-miss candidates. Read the
diagnosis before retrying.

| `kind` | Meaning | What to do |
| --- | --- | --- |
| `invalid_arguments` | An argument is missing or invalid (wrong type, out of range). | Fix the argument the message names. |
| `no_match` | No application or element matched. | Read the candidates in the diagnosis, then correct the selector or target. |
| `ambiguous_selector` | The selector matched several elements where one is required. | Narrow it with an attribute filter or `:nth(n)`. |
| `ambiguous_shell_surface` | Several shell surfaces of the requested kind exist. | Pass the `pid` of the one you mean, from the candidates. |
| `timeout` | An auto-wait ran out before its condition held. | Read `last_observed`. "never matched" means the selector is wrong. A state such as `visible=false` means the element exists and cannot be acted on yet. |
| `element_stale` | The element vanished between being found and being acted on. | Run the lookup again. |
| `action_not_supported` | The element cannot perform this verb. | Pick another verb from the element's properties. |
| `text_value_not_supported` | The platform cannot set text on this element. | Use `type-text`, or the `type` tool after focusing the element. |
| `invalid_selector` | The selector failed to parse. | Fix the syntax the message points to. |
| `invalid_action_data` | An action payload failed validation. | Fix the value, point, size or range. |
| `invalid_text_range` | A text range is reversed, past the end of the text, or splits a surrogate pair. | Read `text_range.length`, the text's current length, and take offsets from a fresh `text` result. |
| `invalid_config` | Process configuration is invalid, such as a malformed `XA11Y_DEFAULT_TIMEOUT`. | Fix the server's environment and restart it. |
| `no_element_bounds` | The element has no screen bounds. | Use `action`, which needs none, or scroll the element into view first. |
| `unsupported` | No backend covers this operation on this platform or session. | Use another approach. Retrying cannot succeed. |
| `permission_denied` | An OS permission is missing. | Relay the instructions in the message to the user. |
| `accessibility_not_enabled` | The application exposes an empty tree because its accessibility bridge is off. | Relay the fix in the message to the user. The application needs a restart afterwards. |
| `subscription_expired` | An event subscription handle expired. | Start a new subscription with `events_start`. |
| `subscription_not_found` | An event subscription handle was never issued. | Use the handle `events_start` returned. |
| `platform` | The OS accessibility API failed. | Retry once, then report the message. |
| `unknown` | An error this build does not classify. | Report the message. |

## Events

`events_start` returns a handle, `events_poll` drains what has been buffered,
and `events_stop` closes the subscription. Start the subscription before the
action you want to observe. An event is a snapshot from when it fired, so read
the tree again to see the current state.

## Platform notes

- macOS: the process running xa11y needs the Accessibility permission, and
  screenshots also need Screen Recording. Without them every call fails with
  `permission_denied`.
- macOS: a Chromium or Electron application builds its web content's tree
  only on request. A `web_area` with no children is the sign. Call
  `enable_web_accessibility` on the application, then search again.
- Linux: AT-SPI2 must be running on the session bus. Chromium and Electron
  applications need `--force-renderer-accessibility`, or they report
  `accessibility_not_enabled`.
- Windows: screen coordinates are physical pixels. On macOS and Linux they are
  logical points.
- Element handles go stale whenever the application rebuilds its UI.
  Selectors re-resolve on every call, so address elements by selector and not
  by remembered position.
