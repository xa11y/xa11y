The `xa11y` command-line tool mirrors the library API. It is the fastest way to
inspect an application before writing code against it.

Install it with `cargo install xa11y`, `pip install xa11y`, or
`npm install @crowecawcaw/xa11y`. All three provide the same command, built
from the same Rust code. See
[Install xa11y](/guides/install/#install-the-cli).

For the task of arriving at a working selector, see
[Find the right selector](/guides/debug-selectors/). If you're looking to build
agents that control desktop applications, two purpose-built tools are built on
xa11y: [agent-desktop.dev](https://agent-desktop.dev) as a CLI, and
[strands-xa11y](/guides/strands/) as a tool for agents
built with [Strands](https://strandsagents.com), AWS's open-source agent SDK.

## Commands

### `xa11y apps`

List running applications with their PIDs.

```bash
xa11y apps
```

```
1234	Calculator	focused
5678	Slack
9012	Firefox
```

Columns are tab-separated: process ID, then name. The foreground application
carries a third column, the literal token `focused`. An application whose
process ID cannot be resolved shows `-` in the first column.

On macOS, when the accessibility permission is missing, the command's error is
followed by an interactive prompt offering to open System Settings on the
matching pane (`open` on the deep link). The pane is named for the running
macOS version: `Privacy & Security → Accessibility` through macOS 26, and
`Privacy & Security → Device Control and Data Access` on macOS 27 and newer,
where the `Accessibility` entry no longer exists. The prompt only appears when
standard input is a terminal; scripts and pipes get the error message alone.
The same prompt follows the equivalent failure of every other command that
reads the accessibility tree.

### `xa11y shell`

List the OS shell surfaces currently present.

```bash
xa11y shell
```

```
taskbar	1204	Taskbar
desktop	1204	Desktop
flyout	5120	System tray overflow window
```

Columns are tab-separated: kind, process ID, then name. A surface whose process
ID cannot be resolved shows `-` in the second column. The listing is live, so a
`flyout` appears only while it is on screen. Enumerating never opens or presses
anything.

The kind column, what each kind maps to per platform, and the query API in
every language are in [Shell surfaces](/reference/shell/).

### `xa11y windows`

List top-level windows.

```bash
xa11y windows --pid 1234
```

```
window "Calculator" [enabled visible] bounds=(0,0,400,600)
window "Settings" [enabled visible] bounds=(20,20,300,200)
(2 windows)
```

Without `--app` / `--pid` every running application is enumerated and all
top-level windows are listed; with either filter only that application's
windows are shown. Every window is listed exactly once. On macOS a single
Application entry covers the process and each enumerated window keys
uniquely, so a window is never dropped for sharing an identity with another
(macOS `AXIdentifier` is not unique per window). On Linux, where AT-SPI may
register several Application entries for one process (a main entry plus
per-event-loop pieces), the same-pid entries are deduplicated by the
`(bus_name, stable_id)` identity, so a process's windows are process-complete
rather than the entries themselves being one-per-process. Each line is one
window rendered like `xa11y find` renders elements, with its `actions`
including the window verbs below. A window state the platform cannot report
(`minimized`, `maximized`, `fullscreen`) is simply absent from the line
rather than shown as a guessed `false`.

### `xa11y enable-web-accessibility`

Ask a Chromium or Electron application to build its web content's
accessibility tree, then wait for that content to appear (macOS only).

```bash
xa11y enable-web-accessibility --app "Visual Studio Code"
```

```
web accessibility enabled for "Visual Studio Code" (pid=4242)
```

The command sets the switch, then waits up to the default timeout until some
web area in the app has at least one child, so it succeeds when any one web
area is populated and says nothing about the others. It leaves the switch set
on the app and does not restore it. Linux and Windows have no such request, so
the command exits 1 with guidance for that platform. See
[Platform Details](/reference/platform-details/#macos-electron-and-chromium-apps).

### `xa11y tree`

Print the accessibility tree for an application, read breadth-first up to
2,000 nodes. `--max-nodes N` raises or lowers that limit, and `--max-depth N`
stops at depth N (the application is depth 0).

```bash
xa11y tree --app Calculator
xa11y tree --app Firefox --max-nodes 10000 --max-depth 8
```

```
application "Calculator" [enabled visible]
├── window "Calculator" [enabled visible] bounds=(0,0,400,600)
│   ├── group "Display" [enabled visible]
│   │   └── static_text "Result" value="42" [enabled visible]
│   └── group "Keypad" [enabled visible]
│       ├── button "7" [enabled visible focusable] actions=[press,focus]
│       ├── button "8" [enabled visible focusable] actions=[press,focus]
│       └── button "+" [enabled visible focusable] actions=[press,focus]
└── menu_bar [enabled visible]
```

This is the fastest way to understand an app's structure. Every element shows its role, name, value, states, bounds, and available actions.

A node whose children were cut ends with a line such as `… 12 more (cut by
--max-nodes)`, and a cut tree ends with a summary line,
`(truncated: 2000 nodes shown, cut by the node limit of 2000 (--max-nodes))`.
A subtree whose children could not be read shows `<error: …>` in their place
and the rest of the tree still prints.

`--detail` reads more per element and prints it under the element's line,
before its children. It takes a comma-separated list of `text`, `formatting`,
and `relations`, the names the MCP `tree` tool takes as `detail`:

```bash
xa11y tree --app TextEdit --detail text,relations
```

```
text_field "Email" [enabled visible editable]
  text (15 units): "ada@example.com"
  labelled_by → static_text "Email address"
```

`text` adds each element's full text, its length in UTF-16 code units, and
whether a shared 64 KiB budget cut it. `formatting` adds `text` plus one
`run [START,END): {attributes}` line per formatting run. `relations` adds one
`KIND → role "name"` line per target, marked `(outside the tree)` when the
target was not captured. A read that fails prints `<text error: …>` (or
`formatting` / `relations`) in its place, and a budget that cut the tree is
named in the summary line.

The same output is available in-code via `Element.dump()` (and `Element.tree()` for a structured snapshot) in every language binding. See [Find the right selector](/guides/debug-selectors/#read-the-tree-from-code-instead) for examples.

### `xa11y find`

Find elements matching a CSS-like selector.

```bash
xa11y find "button" --app Calculator
```

```
button "7" [enabled visible focusable] actions=[press,focus]
button "8" [enabled visible focusable] actions=[press,focus]
button "+" [enabled visible focusable] actions=[press,focus]
(3 matches)
```

A selector that matches nothing is an **error**, not an empty result. The
command prints `no elements matched selector: <selector>` and exits non-zero,
which is what makes it usable as a shell assertion.

Use this to test selectors before putting them in code:

```bash
# Does this selector match what I expect?
xa11y find "text_field[name^='Message']" --app Slack

# How many list items are there?
xa11y find "list > list_item" --app Finder
```

`-o` selects the output format: `pretty` (the default, shown above), `bounds`,
or `center`. On Linux with the uinput input backend, which Wayland sessions
use, `-o center` fails with an operation error, because element bounds there
are not screen coordinates. Act on the element with `xa11y action` instead.

`--stable` waits until visible bounds are observed unchanged for at least
750 ms across repeated fresh polls, then prints the match. It waits up to the default
timeout (5 s, or `XA11Y_DEFAULT_TIMEOUT` seconds). With `--stable` the selector
must match exactly one element: several matches is an operation failure that
lists the candidates, and a selector still matching nothing once the wait is
over fails the same way as without the flag. A match that never holds still
fails with a timeout naming the last differing bounds and the latest unchanged
duration. Changed, missing, hidden, or bounds-less observations restart the
window. This measures observed geometry; native snapshots can lag motion.

### `xa11y action`

Perform an action on the first element matching a selector.

```bash
xa11y action press "button[name='7']" --app Calculator
```

```
ok
```

Actions that need a value use `--value`:

```bash
xa11y action set-value "text_field[name='Search']" --app Safari --value "hello"
xa11y action set-numeric-value "slider[name='Volume']" --app Music --value 88
xa11y action type-text "text_field[name='Message']" --app Slack --value "ship it"
```

`select-text` takes its range as `--range START,END`, the spelling `xa11y
text` uses, so a range copied from `text` output fits as is. `--value
START,END` is accepted too, but not together with `--range`:

```bash
xa11y action select-text "text_field" --app TextEdit --range 0,5
```

Window actions use `--at` and `--size` instead:

```bash
xa11y action activate "window" --pid 1234
xa11y action move-to "window[name='Dialog']" --pid 1234 --at 100,200
xa11y action resize-to "window[name='Dialog']" --pid 1234 --size 640,480
```

Each of these flags applies only to the verbs listed for it. `--value` goes
with `set-value`, `set-numeric-value`, `type-text`, and `select-text`;
`--range` with `select-text`; `--at` with `move-to`; `--size` with
`resize-to`. Given to any other verb, the flag is a usage error (exit 2)
naming the verbs that take it, so `xa11y action press button --value x`
fails instead of pressing. The MCP `action` tool refuses `value`, `start`,
`end`, `at`, and `size` the same way, with `invalid_arguments`.

`set-value` writes text. A slider, spin button, or progress bar carries a
number instead, and rejects text with `TextValueNotSupported`; use
`set-numeric-value`, which takes any finite number and does in one call what
`increment` would take a step at a time.

Window verbs are only meaningful on window-like elements: `window`, or
`dialog`, which every platform surfaces as a top-level window. `move-to` and
`resize-to` take **logical** screen coordinates (the same space as the
`bounds=()` in `xa11y find` output). Window verbs use either an accessibility
API or a capability-detected native window-manager API. X11 supports EWMH and
ICCCM operations. Sway supports activation, fullscreen, restore, and close;
its model has no minimize or distinct maximize state. macOS cannot maximize,
and Windows cannot enter fullscreen. An unavailable operation exits non-zero
with `Unsupported`; it never falls back to input simulation.

`restore` is the inverse of all three entry verbs (`minimize`, `maximize`,
`enter-fullscreen`): it leaves whichever special state is set. There is no
separate exit-fullscreen action — on macOS the only absolute exit is the same
`AXFullScreen=false` write, so a second verb would be a second name for it.

#### Available actions

| Action | Description |
| --- | --- |
| `press` | Press a button or invoke a control |
| `focus` | Move focus to the element |
| `blur` | Remove focus from the element |
| `toggle` | Toggle a checkbox or switch |
| `expand` | Expand a disclosure or menu |
| `collapse` | Collapse a disclosure or menu |
| `select` | Select an item |
| `show-menu` | Show a context menu |
| `scroll-into-view` | Scroll the element into view |
| `increment` | Increment a numeric value |
| `decrement` | Decrement a numeric value |
| `set-value` | Set text value (requires `--value`) |
| `set-numeric-value` | Set numeric value, for sliders and spin buttons (requires `--value N`) |
| `type-text` | Type text as keystrokes (requires `--value`) |
| `select-text` | Select a text range (requires `--range START,END` or `--value START,END`, in UTF-16 code units) |
| `activate` | Bring the window to the foreground and focus it |
| `minimize` | Minimize the window (leaves fullscreen first on macOS) |
| `maximize` | Maximize the window (Windows `WindowVisualState_Maximized`; unsupported on macOS) |
| `enter-fullscreen` | Put the window in native fullscreen (macOS `AXFullScreen`; unsupported on Windows) |
| `restore` | Restore the window from minimized/maximized/fullscreen |
| `close` | Close the window |
| `move-to` | Move the window (requires `--at X,Y`) |
| `resize-to` | Resize the window (requires `--size W,H`) |

### `xa11y text`

Read an element's text by range and print the result as JSON.

```bash
xa11y text info "text_area[name='Notes']" --app TextEdit
xa11y text read "text_area[name='Notes']" --app TextEdit --range 0,200
xa11y text bounds "text_area[name='Notes']" --app TextEdit --find Total
xa11y text range-at "text_area[name='Notes']" --app TextEdit --offset 12 --unit word
```

Offsets are UTF-16 code units, so an emoji outside the Basic Multilingual
Plane counts as two. Every range in the output carries `start`, `end`, and the
`text` it covers. Copy those numbers into `select-text` instead of counting
characters.

| Operation | Returns | Flags |
| --- | --- | --- |
| `info` | `length`, `caret`, and the selected ranges | none |
| `read` | The text of the range, at most `--limit` units (default 4096) | `--range` or `--find`, `--limit` |
| `find` | The `--occurrence`-th match of `--find`, or `found: false` | `--find`, `--occurrence`, `--range` to search within |
| `object-at` | The embedded control or link at `--offset` as `object`, one line in the form `find` prints, or `null` when there is none. IA2 only | `--offset` |
| `range-at` | The `--unit` at `--offset`: `character`, `word`, `line`, or `paragraph` | `--offset`, `--unit` |
| `lines` | The rendered lines of the range, `--limit` per page (default 100) | `--range` or `--find`, `--limit` |
| `bounds` | One screen rectangle per rendered line of the range | `--range` or `--find` |
| `runs` | Formatting runs of the range, `--limit` per page (default 100) | `--range` or `--find`, `--limit` |

`--range START,END` defaults to the whole text. `--find TEXT` names the range
by its text instead: the match, counted from 0 by `--occurrence`, is the range.
A page that stops early reports `truncated: true` and a `next_start` to resume
from. A flag the operation does not use is a usage error.

The selector must match exactly one element. The command waits up to the
default timeout for it to be present, and does not require it to be visible.

### `xa11y table`

Ask a table about its structure. Each match prints on one line, as `find`
prints it.

```bash
xa11y table cell-at "table[name='Prices']" --app Numbers --row 2 --column 0
xa11y table column-header-cells "table_cell[row='2'][column='1']" --app Numbers
```

| Operation | Acts on | Returns |
| --- | --- | --- |
| `cell-at` | a table | The cell covering `--row` and `--column`, including a merged cell |
| `column-headers`, `row-headers` | a table | Its header cells |
| `column-header-cells`, `row-header-cells` | a cell | The headers that head it |
| `selected-items` | a list, tree, table, or tab list | The selected items |

Indices count from 0. A cell by position is also a selector,
`table_cell[row="2"][column="0"]`, and `find` and `tree` show each element's
`row`, `column`, `index`, `size`, and related positions under the same names
the selector uses.

### `xa11y relations`

List the elements one element is related to, grouped by kind. Name the kinds
to read, or give none for every kind this platform reports.

```bash
xa11y relations "text_field[name='Email']" labelled_by described_by --app Firefox
xa11y relations "button[name='Menu']" --app Firefox
```

The selector must match one element. Each kind prints a header with its count,
then its elements indented, one per line as `find` prints them. A kind with no
targets prints a count of 0. A kind the platform never reports is an error.
The kinds are `labelled_by`, `label_for`, `described_by`, `description_for`,
`details`, `details_for`, `controls`, `controlled_by`, `flows_to`,
`flows_from`, `error_message`, `error_for`, `owns`, `member_of` and `linked`.

### `xa11y events`

Stream accessibility events in real time. Runs until you press ctrl-c.

```bash
xa11y events --app Calculator
```

```
[focus_changed] button "7"
[value_changed] static_text "Result"
[focus_changed] button "+"
[state_changed] check_box "Wrap" Checked=true
[value_changed] static_text "Result"
```

Event type names are `snake_case`, matching the roles in the same output and
the `event_type` strings the Python binding reports. See
[Events](/reference/events/) for the full list. A target that could not be
resolved prints as `-`, and a `state_changed` line appends the flag and its
new value. An `announcement` line appends its origin, politeness and text.

`--kinds announcement,focus_changed` prints only those kinds. An unknown name is
a usage error, and a kind this platform never sends fails at once with the
capability table's reason.

Useful for understanding what events fire when you interact with an app, or for debugging event subscriptions in your code.

### `xa11y capabilities`

Print what this platform's backend can report, one feature per line:
`supported`, `partial` (some toolkits, apps or display servers only) or
`unsupported`, with a note where there is one. It reads a fixed table and
touches no application. The table is the one under
[Capabilities](/reference/platform-details/#capabilities).

```bash
xa11y capabilities                          # this platform, every feature
xa11y capabilities window: event:menu_opened
xa11y capabilities --platform windows --os-version 10.0.19045 --json
```

Positional arguments select features by name (`event:menu_opened`) or by
area (`window:`). An unknown name is a usage error that lists the closest
known names. `--platform` takes `linux`, `macos` or `windows`, and
`--os-version` narrows the answers to that release. Linux has no platform
version, so it takes none. Text output starts with a `platform:` line,
followed by `name`, `support` and `note` columns separated by tabs. `--json`
prints one object with `platform`, `os_version` and `capabilities`.

### `xa11y guide`

Print the [agent guide](/guides/agent-guide/): the guide an agent reads
before driving xa11y. It is compiled into the binary, so it matches the build
that prints it. `xa11y mcp` serves the same text.

```bash
xa11y guide
```

The command takes no arguments.

## `xa11y screenshot`

Captures pixels and writes them as a PNG. With `--annotate` it also reads the
accessibility tree, draws an outlined box over every element a selector
matches, and prints a legend.

```bash
xa11y screenshot [--region X,Y,W,H] --out PATH
                 [--app NAME | --pid PID | --shell KIND]
                 [--annotate SELECTOR]...
                 [--legend text|json|none]
```

| Flag | Description |
| --- | --- |
| `--out PATH` | Required. Writes the PNG to `PATH`, or to stdout for `-` |
| `--region X,Y,W,H` | Captures this rectangle in desktop coordinates (physical pixels on Windows, logical points elsewhere). Omitted, the capture is whatever the platform treats as the whole screen: the virtual desktop on Windows, one display on macOS, the root window on Linux |
| `--app NAME` / `--pid PID` / `--shell KIND` / `--backend B` | The target whose tree `--annotate` searches, as described under [Flags](#flags) |
| `--annotate SELECTOR` | Repeatable. One annotation group per occurrence |
| `--legend text\|json\|none` | Legend format on stdout. Defaults to `text` |

Without `--annotate` the command reads no accessibility data, takes no target,
and prints nothing on stdout. A capture written to a file reports its
dimensions on stderr.

### `--annotate`

Each occurrence is one group. A group has a letter (`A`, `B`, and so on past
`Z` as `AA`), a colour from a seven-entry palette that cycles, and one box per
element its selector matches inside the target. A box carries a tag of the
group letter and a 1-based index, so `B7` is the seventh match of the second
`--annotate`. That index is the `:nth(n)` argument in the entry's selector.

Selectors are the same syntax the library takes; see
[Selectors](/reference/selectors/). A comma-separated alternation is refused
with `InvalidSelector`, because `<selector>:nth(n)` would bind to its last
clause alone. Pass one `--annotate` per clause.

Cropping and annotating are independent. `--region` chooses what is captured
and `--annotate` chooses what is drawn on it, so a match outside the captured
area is reported as omitted rather than clamped to an edge.

At most 100 elements are described across all groups, counting drawn boxes and
omitted elements. Matches past the cap are neither drawn nor listed.

For the task, see
[Annotated screenshots](/guides/annotate-screenshots/).

### `--legend`

`text` writes a group header block, one line per box, then a summary of what
was omitted and what the cap cut off:

```
A  button      #E69F00  3 annotated
B  text_field  #56B4E9  1 annotated

A1  button      "7"        bounds=104,318,48,44  button:nth(1)
A2  button      "8"        bounds=156,318,48,44  button:nth(2)
A3  button      "9"        bounds=208,318,48,44  button:nth(3)
B1  text_field  "Display"  bounds=100,60,320,52  text_field:nth(1)

omitted: 1 element (outside_capture: button "Paste")
truncated: 37 more elements matched but were not described (cap: 100)
```

A group with no matches still gets a header line. An element with no accessible
name shows `-` in the name column, which keeps it distinct from one named with
the empty string. The omission summary lists at most five elements inline.

Once the cap has been reached, each header line from the first affected group
onward carries a parenthetical, because its count is a lower bound:

```
B  button     #56B4E9  62 annotated  (cap reached, so more may have matched)
C  menu_item  #009E73  0 annotated  (cap reached at or before this group, so 0 is not "matched nothing")
```

Groups resolve in `--annotate` order and resolution stops at the cap, so the
groups before the first affected one are exact. A group starved by the cap
would otherwise read the same as one whose selector reached nothing.

`json` writes one object instead, with `groups` (letter, selector, colour,
count, and `capped` per group), `legend`, `omitted`, `truncated`, and `cap`. It
carries the whole omission list.

`capped` is the boolean behind the parentheticals above. `true` means the cap
may have shortened this group, so `"annotated": 0` alongside it does not mean
the selector matched nothing. It is `false` on every group when `truncated` is
`0`.

`none` suppresses the legend and leaves stdout empty.

### Usage errors

These four exit with code 2 before any capture is taken.

| Invocation | Message names |
| --- | --- |
| `--annotate` with no `--app`, `--pid`, or `--shell` | The three target flags |
| `--out -` together with a legend | `--out FILE`, or `--legend none` |
| `--legend` with no `--annotate` | Adding `--annotate SELECTOR`, or dropping `--legend` |
| `--app`, `--pid`, `--shell`, or `--backend` with no `--annotate` | The flags passed, `--annotate SELECTOR`, and `--region X,Y,W,H` |

PNG bytes and legend text cannot share stdout, so the second refuses rather
than moving the legend to stderr, where a caller piping the image would never
learn that it went elsewhere. A `--legend` value outside `text`, `json`, and
`none` is a usage error as well.

## `xa11y mcp`

Serves the commands above as [Model Context Protocol](https://modelcontextprotocol.io)
tools over stdio. An MCP client launches it as a subprocess and speaks JSON-RPC
on its standard streams, one message per line. It is not meant to be run by
hand.

```bash
xa11y mcp
```

The same server ships in all three packages, because all three launchers run
the same Rust implementation. To wire it into a client, see
[Serve xa11y over MCP](/guides/mcp/).

### Protocol revisions

The server is dual-era. It answers `server/discover` for clients on the
stateless revisions (`2026-07-28` and later) and `initialize` for clients that
open with a handshake (`2025-11-25`, `2025-06-18`, `2025-03-26`). A request
naming a revision it does not speak gets a `-32022` error listing the ones it
does.

### Tools

Each tool takes the arguments its CLI counterpart takes as flags. The
accessibility tools need `app`, `pid`, or `shell`. The input tools take screen
coordinates and no target. `screenshot` takes a target only when `annotate`
gives it selectors to resolve.

| Tool | Arguments |
| --- | --- |
| `apps` | none |
| `capabilities` | `platform`, `os_version`, `names`, `backend` |
| `shell` | none |
| `windows` | `app`, `pid`, `backend`, `limit` |
| `enable_web_accessibility` | `app`, `pid`, `backend` |
| `tree` | `app`, `pid`, `shell`, `backend`, `max_depth`, `max_nodes`, `detail` |
| `find` | `selector`, `app`, `pid`, `shell`, `backend`, `limit`, `stable` |
| `action` | `action`, `selector` or `ref`, `app`, `pid`, `shell`, `backend`, `value`, `start`, `end`, `at`, `size` |
| `text` | `op`, `selector` or `ref`, `app`, `pid`, `shell`, `backend`, `start`, `end`, `find`, `occurrence`, `offset`, `unit`, `limit` |
| `table` | `op`, `selector` or `ref`, `app`, `pid`, `shell`, `backend`, `row`, `column`, `limit` |
| `relations` | `selector` or `ref`, `app`, `pid`, `shell`, `backend`, `kinds`, `limit` |
| `click` | `x`, `y`, `button`, `count`, `held` |
| `move` | `x`, `y` |
| `drag` | `from_x`, `from_y`, `to_x`, `to_y`, `button`, `duration_ms`, `held` |
| `scroll` | `x`, `y`, `dx`, `dy` |
| `key` | `key`, `held` |
| `type` | `text` |
| `screenshot` | `x`, `y`, `width`, `height`, `annotate`, `app`, `pid`, `shell`, `backend` |
| `events_start` | `app`, `pid`, `backend`, `kinds` |
| `events_poll` | `subscription_id`, `max`, `timeout_ms` |
| `events_stop` | `subscription_id` |

`text` and `table` take the operations of [`xa11y text`](#xa11y-text) and
[`xa11y table`](#xa11y-table) as `op`. `text` spells `--range` as `start` and
`end`, and so does `action` for `select-text`. `tree` spells `--max-nodes` as
`max_nodes` and `--detail` as `detail`, an array.

`action` accepts the same verbs as [`xa11y action`](#xa11y-action). `key`
accepts the same key names as [`xa11y key`](#input-simulation). Selectors are
the same syntax the library takes; see [Selectors](/reference/selectors/).

Every `tree` node, `find` match, `windows` window, `relations` target,
`table` element, and `text` `object-at` result carries a `ref` such as `c3:17`. `action`, `text`,
`table` and `relations` take one in place of `selector` (and then no `app`,
`pid`, `shell` or `backend`), and act on exactly that element. A ref is never
re-resolved by selector: an element that was removed or replaced fails with
`element_stale` and a `stale_reason`. The server keeps the refs of its 8 most
recent results that returned elements, and an older ref fails with
`ref_expired`. An index past the end of a result the server still holds was
never issued, and fails with `invalid_arguments`. Event targets carry no ref:
each is a snapshot from when the event fired. The command line has no refs, because each invocation is
a new process.

`shell` takes a kind string, is mutually exclusive with `app`, and combines
with `pid`. A kind matching several surfaces comes back as an
`ambiguous_shell_surface` failure with the candidates listed. See
[Shell surfaces](/reference/shell/).

The `windows` tool is the MCP counterpart of [`xa11y windows`](#xa11y-windows):
without `app`/`pid` it lists the top-level windows of every running
application, with either it lists those of that one. Results are capped at
`limit` (default 50) and report `truncated` when anything was dropped.

`annotate` is an array of selectors, one annotation group per entry, and it is
`screenshot`'s counterpart to the CLI's repeatable `--annotate`. Every element
a selector matches gets an outlined box and a tag drawn on the capture, and the
result gains `legend`, `omitted`, and `truncated` alongside the image. It reads
the accessibility tree, so it needs `app`, `pid`, or `shell`. That target
scopes the selectors and leaves the captured area to `x`, `y`, `width`, and
`height`. At most 100 elements are described; `truncated` counts the matches
past that cap. See [Annotate a screenshot](/guides/mcp/#annotate-a-screenshot).

The `action` tool differs from `xa11y action` in one way, deliberately. The
command acts on the first match, as the library's `Locator` does. The tool
requires the selector to match **exactly one** element and returns an
`ambiguous_selector` failure listing the candidates otherwise, because its
schema promises that and a model told "exactly one" cannot tell that it got
the first of several. Narrow the selector or pick one with `:nth(n)`.

Both surfaces auto-wait: the element has to exist, be visible, and be enabled
before the action runs, within the default timeout (5 seconds, or
`XA11Y_DEFAULT_TIMEOUT` seconds when that is set in the server's environment).
The window verbs (`activate`, `minimize`, `maximize`, `enter-fullscreen`,
`restore`, `close`, `move-to`, `resize-to`) and `scroll-into-view` are the one
exception: they wait only for `enabled`, because a minimized window is
legitimately not visible and must still be reachable by the very verbs that
restore or activate it. A call that is going to fail therefore takes that
long, and no MCP argument shortens it.
`ok: true` reports that the application accepted the call, not that anything
changed; read the tree again to confirm an effect.

An element's `actions` field reports what the application advertises through
the platform's action interface. It is not the set of verbs `action` accepts,
and it is not a capability list: a slider that advertises nothing still
increments. Pick the verb from the element's own properties — `numeric_value`
for the value verbs, an `editable` state for the text verbs.

### Events

[`xa11y events`](#xa11y-events) blocks for as long as you watch, and a tool
call that never returns hangs the client. The MCP counterpart is a trio
instead: `events_start` returns a `subscription_id`, `events_poll` drains what
has arrived, and `events_stop` closes it.

Subscriptions are per application, so `events_start` takes `app` or `pid` and
has no `shell` argument. `kinds` filters what gets buffered; the names are the
ones in [Events](/reference/events/).

Events buffer from the moment `events_start` returns, so a subscription has to
exist before the action it is meant to observe. At most 1024 are held, and past
that the oldest are evicted: `dropped` in each poll result counts what was lost
since the previous poll, `dropped_total` over the subscription's life, and each
event's `sequence` makes the gap visible in the events themselves.

`events_poll` returns at most `max` events (100 by default) and does not block
by default. A `timeout_ms` up to 15000 waits for the first event and returns as
soon as one lands. `live: false` means the platform dropped the subscription,
so nothing further can arrive. It does not report that the application exited:
no platform reports that as a dropped subscription, so an application that
quits keeps returning `live: true` with no events. Call `apps` to find out
whether it is still running.

A handle lives in the server process and no longer. It stops resolving once
`events_stop` closes it, or after five minutes without a poll. Either way the
next call naming it is a `subscription_expired` failure, which is a different
kind from the `subscription_not_found` an id that was never issued gets.

### Results

Every tool returns `structuredContent`, mirrored as JSON in a text block for
clients on revisions that predate `structuredContent`. `find` reports each
match's `bounds` and a precomputed `center`, so a result feeds straight into
`click` or `screenshot` without arithmetic. Where element bounds are not screen
coordinates, on Linux with the uinput input backend, every element-returning
tool omits `center` and its result carries `center_unavailable` with the
reason. With `stable: true`, `find` first
waits for its one match to stop moving, the same as `find --stable`.

Results are bounded, because each one lands in a model's context window.
`tree` walks 12 levels by default and returns at most `max_nodes` nodes
(default 2000, which is also the largest value it accepts);
`find` returns 50 matches by default and never more than 500. `text` reads
4096 UTF-16 code units by default and never more than 65536, and caps the text
on each listed range at 256 units. All of them report whether they truncated.

### Errors

Failures split the way the protocol asks. An unknown tool or a malformed
request is a JSON-RPC error. Everything a model could fix by retrying — a
selector that matched nothing, an application that is not running, a bad key
name, a selector that matched several where one was required — comes back as a
result with `isError: true`, carrying the failure's `kind` and, where the error
has one, its [diagnosis](/explanation/errors-and-diagnosis/): what the operation
was waiting for, what it last observed, and which near-miss elements were
present. `find` and `action` report a miss the same way, so a typo costs one
call from either. The [agent guide](/guides/agent-guide/#failures) lists
every `kind`.

Every failure result also carries `delivery`: `not_delivered` when nothing
reached the application, so the call can be repeated once its cause is fixed,
or `unknown` when the action was dispatched, or may have been, so a retry may
apply it twice. The command line prints the same value after a failed action
command; see [Exit codes](#exit-codes).

### Prompts and resources

The server also serves the [agent guide](/guides/agent-guide/), the text
`xa11y guide` prints, in both protocol eras.

| Surface | Name | Content |
| --- | --- | --- |
| Resource | `xa11y://guide` | The guide as `text/markdown`, from `resources/read` |
| Prompt | `guide` | One user message holding the guide, from `prompts/get`. Takes no arguments |

`resources/templates/list` returns an empty list. An unknown URI or prompt name
is a `-32602` error whose `data.available` names what exists.

## Composing the two halves

`find -o bounds` and `find -o center` emit coordinates in the form the input
and screenshot commands take, which is how an accessibility query drives a
pixel operation:

```bash
region=$(xa11y find 'button[name="OK"]' --app Safari -o bounds)
xa11y screenshot --region "$region" --out button.png

xa11y click --at "$(xa11y find 'button[name="OK"]' --app Safari -o center)"
```

Add `--stable` to the `find` when the target may still be animating into
place, so the click goes to the point where it comes to rest:

```bash
xa11y click --at "$(xa11y find 'button[name="OK"]' --app Safari -o center --stable)"
```

## Flags

The accessibility commands other than `apps` and `shell` require a target. The
input-simulation commands take none of these flags, and `screenshot` takes one
only when `--annotate` gives it selectors to resolve.

| Flag | Description |
| --- | --- |
| `--app NAME` | Target application by exact, case-sensitive name (see `xa11y apps`) |
| `--pid PID` | Target by process ID |
| `--shell KIND` | Target a shell surface by kind (see `xa11y shell`). Mutually exclusive with `--app`; combine with `--pid` to pick between same-kind surfaces |
| `--backend native\|uia\|ia2` | The accessibility source for the application, overriding `XA11Y_ACCESSIBILITY_SOURCE` for that attachment. `uia` and `ia2` require Windows; the [platform matrix](/reference/platform-details/#capabilities) records the capabilities of each. Accepted by `apps` and by every command that takes `--app`, but not together with `--shell`. `capabilities --backend` describes that source |

Each command accepts only the flags it reads. Any other flag, an unknown one,
or a surplus positional argument is a usage error at exit code 2 rather than
being ignored, and so is an unknown `--backend` value.

`tree`, `find`, and `action` accept `--shell` wherever they accept `--app`.
The kinds are listed in [Shell surfaces](/reference/shell/#kinds).

A kind matching several surfaces, and a kind matching none, are operation
failures: exit code 1, with the candidate list on stderr. The invocation was
well formed; the desktop held the wrong number of surfaces. Two argument
mistakes are usage errors at exit code 2: `--shell` passed together with
`--app`, and a kind string that is not a known kind.

`--pid` is the only lever for choosing between same-kind surfaces, and it
does not always separate them. Two Linux panels drawn by one panel process
share a pid, so no `--pid` value narrows that match. The refusal says as
much rather than picking one.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | The operation failed: application not found, no selector match, a platform error |
| `2` | Usage error: an unknown flag, a flag the command does not take, a bad flag value, a missing or invalid argument |

The message goes to stderr. When an action command (`action`, `click`, `move`,
`drag`, `scroll`, `key`, `type`, or `enable-web-accessibility`) fails with
exit code 1, a `delivery:` line follows it:

```
delivery: not_delivered (the action did not reach the application, so a retry is safe)
delivery: unknown (the action may have been applied, so re-read the state before retrying)
```

`not_delivered` means nothing reached the application. `unknown` means the
action was dispatched, or may have been, and its outcome is unconfirmed, so a
retry may apply it twice. It is the same value as the MCP failure's `delivery`
field.

## Selectors

`xa11y find` and `xa11y action` take the same selector syntax as the library.

attributes.

```bash
xa11y find "[focusable='true']" --app Slack
```
