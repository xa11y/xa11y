`Locator` and `Element` are the two ways to reach a node in the accessibility
tree. This page lists what each one offers. Full signatures, including
parameter types and defaults, are in the generated API reference:
[Rust](https://docs.rs/xa11y/), [Python](/api/python/reference/api/xa11y/),
[JavaScript](/api/javascript/).

For the model behind the two, see
[How xa11y works](/explanation/how-it-works/#taking-actions).

## Locator

Created by `app.locator(selector)`, or by the module-level
`xa11y.locator(selector)` for a search rooted at the system rather than at one
application. A `Locator` re-resolves its selector on every operation.

### Actions

`press()`, `focus()`, `blur()`, `toggle()`, `select()`, `expand()`,
`collapse()`, `set_value()`, `set_numeric_value()`, `type_text()`,
`select_text()`, `increment()`, `decrement()`, `show_menu()`,
`scroll_into_view()`, `perform_action(name)`.

Each auto-waits for the target to be visible and enabled before dispatching.
The exception is `scroll_into_view()`, which waits for attached and enabled
alone: an off-screen element is what it exists to bring on-screen, so gating it
on visibility would never resolve.

Waiting includes scrolling. When the target is enabled and
the only thing hiding it is a scrolling ancestor (`hidden_reason` is
`scrolled_out`), the wait calls the platform's own `scroll_into_view` on it and
checks again on the next poll. Nothing is clicked or dragged to get there.
Auto-scroll happens only where the platform reports `scrolled_out`, so in
practice it never happens on macOS, where every hidden element reads
`not_showing`. The call is made under these rules:

- If the platform refuses it for that element, the wait doesn't ask again:
  one refusal per wait. It keeps polling until its timeout, so an element that
  scrolls into view some other way is still acted on.
- If the platform accepts it, the wait always checks the element once more,
  even when the timeout has run out meanwhile, so a scroll that worked is
  never reported as one that didn't.
- If the platform accepts it and the element stays scrolled out, the wait
  calls it at most three times in all.
- Any other failure of the call ends the wait with that error.
- A disabled target is never scrolled, and neither is one hidden for any other
  reason (`not_showing`, `window_minimized`, `unknown`).

When such a wait times out, its diagnosis says how the scroll ended in the
`auto_scroll` field: `refused`, `no_effect` (accepted, and the next poll still
read the element not visible, whether scrolled out or hidden for another
reason), or `revealed` (the next poll read it visible, and something else,
such as `enabled=false`, kept the wait going). The field describes the first
poll after the latest accepted scroll, so `revealed` alongside a
`hidden_reason` of `scrolled_out` means the element came into view and later
scrolled back out. `last_observed` says the same in prose. No `auto_scroll`
means the wait never tried to scroll. See
[errors](/reference/errors/#structured-fields).

`Element` actions and the `wait_*` family don't scroll. Platform limits, such
as which controls have a scroll call at all, are in
[Platform Details](/reference/platform-details/).

Which platform API each verb reaches is in
[Platform Details](/reference/platform-details/#action-mapping).

### Waits

`wait_visible()`, `wait_hidden()`, `wait_attached()`, `wait_detached()`,
`wait_enabled()`, `wait_disabled()`, `wait_focused()`, `wait_unfocused()`,
`wait_stable()`, `wait_until()`.

Each polls until the condition holds or the timeout expires, then raises
`Timeout` with a diagnosis. `wait_until()` takes a predicate over the resolved
element, which is `None` when the selector did not match.

`wait_stable(timeout)` (`waitStable` in JS) returns the element once its
bounds are observed unchanged for at least 750 ms while visible. It is
about geometry and unrelated to an element's `stable_id`. Call it before
pointing at an element that may still move. Each poll performs a fresh resolve
roughly every 100 ms. Even a still element needs at least 750 ms after the
first observation.

A change in bounds restarts the observation window. A missing or hidden match
also restarts it. An element with absent bounds cannot count as stable.
The window exceeds Chromium's 500 ms publication interval for location changes
in elements without focus. Equal native reads can otherwise be the same
cached position during motion. This measures observed geometry. Native
snapshots can lag the screen. Motion can resume after a pause.

Only bounds are compared. Replacing an element with another at identical
bounds continues the window. On timeout the diagnosis names the last differing
rectangles and how long the latest bounds were observed unchanged. Other
observations are `matched but not visible`, `reports no bounds`, or
`selector never matched`.

Rust adds `wait_for_state()`, a generic wait over the `ElementState` enum. The
bindings expose the specific `wait_*` helpers above and `wait_until()` in its
place.

### Queries

| Method | Returns |
| --- | --- |
| `element()` | The first match in document order, or the `nth()` index when one is set. Raises `SelectorNotMatched` when there is none. Several matches is not an error. |
| `elements()` | Every match |
| `exists()` | Boolean |
| `count()` | Number of matches |

### Chaining

`nth(n)`, `first()`, `child(selector)`, `descendant(selector)`.

`child()` and `descendant()` distribute over every clause of an alternation
selector. See [Selectors](/reference/selectors/#alternation-selector-groups).

## Element

A live handle returned by `app.children()`, `element.children()`,
`element.parent()`, `locator.element()`, or `locator.elements()`.

### Properties

| Property | Type |
| --- | --- |
| `role` | Normalized role, `snake_case` |
| `name` | String, optional |
| `value` | String, optional |
| `description` | String, optional |
| `bounds` | Rect (`x`, `y`, `width`, `height`), optional |
| `states` | State set (`enabled`, `visible`, `focused`, and the rest) |
| `actions` | List of action names this element supports |
| `numeric_value` | Number, optional |
| `min_value` | Number, optional |
| `max_value` | Number, optional |
| `stable_id` | String, optional |
| `table` | Table size (`row_count`, `column_count`), optional |
| `cell` | Cell position (`row`, `column`, `row_span`, `column_span`, `header`), optional |
| `table_row` | Row position (`index`), optional |
| `collection` | Position in a list or tree (`index`, `size`, `depth`), optional |
| `heading_level` | Integer, optional. `1` is an h1. |
| `landmark_type` | Landmark kind (`main`, `navigation`, `contentinfo`, and the rest), optional, on a `landmark` |
| `web_role` | The ARIA role a web page gave the element, optional |
| `link_url` | A link's target URL, optional. The selector attribute is `url`. |
| `live_region` | Live-region settings (`politeness`, `atomic`, `relevant`), optional |
| `pid` | Process ID of the owning application |
| `raw` | Platform-native key/value map |

`name`, `value`, and `description` are stripped of Unicode bidi format
controls. `raw` holds the unstripped platform string under the platform-native
key. Each of these properties except `raw`, `states`, and `actions` is also
usable as a selector attribute, along with the individual state flags.
`pid` is the exception, having no attribute of its own. `link_url` matches as
`url`, and `live_region` as `live` (its politeness). `table`, `cell`,
`table_row`, and `collection` are matched through their fields, as
[numeric attributes](/reference/selectors/#numeric-attributes). See
[Selectors](/reference/selectors/#attributes).

In `table`, `cell`, `table_row`, and `collection`, every index (`row`,
`column`, `index`, `depth`) is 0-based. The whole property is absent when the
element has no such semantics, and each field is absent when the platform did
not report it. `row_count`, `column_count`, and `size` are an integer or the
string `"unknown"`. Platform support is in
[Platform Details](/reference/platform-details/#tables-collections-and-text).

### Navigation and snapshots

| Method | Returns |
| --- | --- |
| `children()` | Direct children, queried from the platform on each call |
| `parent()` | The parent element |
| `tree(max_depth)` | The subtree as a structured snapshot (`role`, `name`, `value`, `children`) |
| `dump(max_depth)` | The same snapshot as an indented string |

`max_depth` of `0` returns the root node alone, `1` adds its direct children,
and so on. Omit it for the full subtree. `tree()` and `dump()` are also
available on `App` and `Locator`.

### Bounded capture

`capture()` reads a subtree into a flat list of nodes under explicit limits,
and reports which limit cut it. It is on `Element`, `App`, `Locator` and
`ShellSurface`. Use it in place of `tree()` for a large or unknown tree.

| Option | Default | Meaning |
| --- | --- | --- |
| `max_depth` | none | Deepest level read; the root is depth 0 |
| `max_nodes` | 2000 | Most nodes, the root included |
| `detail` | none | `text` reads each element's text, `relations` its relations |
| `max_text_bytes` | 65536 | Total text budget for `text` detail |
| `timeout` | none | Seconds in Python, milliseconds in JavaScript |

The tree is read breadth-first and listed in pre-order, so when `max_nodes`
cuts, the top of the tree is complete. Each node carries its `index`,
`parent`, `depth`, the `element` itself, its `children` as indices,
`children_count` (its real number of children) and `children_truncated`.
`truncated` on the capture has `by_depth`, `by_nodes`, `by_text` and
`by_time`, each set only when that limit left something out.

Each node is read once, at some moment while the capture runs, so the result
is not an atomic snapshot of the app. Nodes that disappear mid-read are
dropped and counted in `vanished`, and any other failed read is kept in that
node's `errors` while the walk carries on. When the time budget runs out, the
call still returns, with what it read and `truncated.by_time` set.

A node's `element` names exactly that node, so an action on it reaches it or
raises `ElementStaleError`. With `relations` detail, a target inside the
capture is the `int` index of its node and a target outside it is an
`Element`.

```python
cap = app.capture(max_nodes=5000, detail={"text"})
for node in cap.nodes:
    if node.children_truncated:
        print("cut at", node.role, node.name, node.children_count)
article = next(n for n in cap.nodes if n.element.landmark_type == "main")
print("".join(n.text.content for n in cap.subtree(article.index) if n.text))
```

### Tables and text

| Method | On | Returns |
| --- | --- | --- |
| `text()` | Any element with a text interface | A `Text` bound to this element. Raises `ActionNotSupported` when there is no text interface. |
| `cell_at(row, column)` | A table | The cell at that 0-based slot, the merged cell covering it, or none |
| `column_headers()`, `row_headers()` | A table | Its header cells |
| `column_header_cells()`, `row_header_cells()` | A cell | The header cells that head it |
| `selected_items()` | A list, tree, table, or tab list | The selected rows or cells |

### Relations

| Method | Returns |
| --- | --- |
| `relations(kinds)` | The elements this one is related to, per kind. Its label is `labelled_by` and its hint `described_by`. The reverse of each kind is a kind too (`label_for`). |

Each requested kind appears once, in request order, with an empty list when
there are none. Python returns a `dict` keyed by kind and JavaScript an array
of `{ kind, elements }`. With no kinds it reads every kind the platform reports,
the `relation:*` rows of [`capabilities()`](/reference/platform-details/#capabilities).
A kind the platform never reports raises `Unsupported`. macOS reports
`aria-controls` and `aria-flowto` together as `linked`, and Windows reports
`aria-details` as `details`, because the platforms do not tell them apart.

`Locator.text()` returns a `Text` that re-resolves the selector on every read,
waiting until it matches. It does not wait for visible or enabled.

## Text

Every `Text` method is a live platform read. Offsets are 0-based UTF-16 code
units, and a range is half-open, `[start, end)`. Python also accepts a
`(start, end)` tuple as a range, and JavaScript a `{ start, end }` object.

| Method | Returns |
| --- | --- |
| `length()` | Length in UTF-16 code units |
| `caret()` | The caret offset, or none when the element has no caret |
| `selections()` | Selected ranges in document order; empty when nothing is selected |
| `read(range)` | The text in `range`, with bidi controls kept |
| `read_all()` | The whole text |
| `find(needle, occurrence, within)` | The `occurrence`-th (0-based) exact, case-sensitive match, or none. Rust splits the options into `find_with(needle, FindOptions)`. |
| `range_at(offset, unit)` | The `character`, `word`, `line` (rendered), or `paragraph` containing `offset` |
| `lines(range, limit)` | A page of rendered lines: `lines`, `truncated`, `next_start` |
| `runs(range, limit)` | A page of formatting runs: `runs`, `truncated`, `next_start`. Each run has a `range` and `attributes`. |
| `bounds(range)` | One screen rectangle per rendered line fragment, in `bounds` coordinates. At most 1000 lines. |

`limit` defaults to 200 in Python and JavaScript. Run attributes are
`font_family`, `font_size` (points), `font_weight` (CSS scale), `italic`,
`underline`, `strikethrough`, `foreground` and `background` (`"#rrggbb"` or
`"#rrggbbaa"`), `script` (`baseline`, `superscript`, `subscript`), and
`spelling_error`. Each is absent when the platform did not report it.

`select_text(start, end)` on `Locator` and `Element` takes the same offsets.
The bindings also accept a single range: `select_text(range)` in Python and
`selectText(range)` in JavaScript.

### Actions

The same action verbs listed for `Locator` are available on `Element`. The
difference is what they act on:

| | `Locator` | `Element` |
| --- | --- | --- |
| Selector | Re-resolved on every call | Not applicable; the handle is fixed |
| Auto-wait | Waits for visible and enabled, scrolling a scrolled-out target into view | None |
| Node went away or was replaced | Re-resolves against the current tree | Raises `ElementStale` with a `reason`, before acting |
| Equality | Not applicable | `==` (Python) / `sameAs` (JS) compares platform identity, not role and name |

## Default timeout

Auto-waiting actions, the `wait_*` family, and application lookup share one
process-wide default of **5 seconds**. Resolution runs from most to least
specific: an explicit per-call `timeout` argument, then
`set_default_timeout()`, then the `XA11Y_DEFAULT_TIMEOUT` environment variable
(seconds, read once at startup), then the built-in 5 seconds. A timeout of `0`
means a single attempt with no polling.

An unparsable `XA11Y_DEFAULT_TIMEOUT` raises `InvalidConfig`. See
[Errors](/reference/errors/).
